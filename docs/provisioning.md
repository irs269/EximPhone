# Desk phones: provisioning and operation

## Concepts

- One **device** = one SIP account (`devices` table). A user can have several devices (desk phone, softphone); all of them ring together (forking). The account name (`sip_username`) is unique per device (`2007`, `2007-2`, ...); the phone registers *as* the user's extension.
- Passwords are generated by EximPhone, shown **once** to the administrator, and stored sealed (AES-256-GCM, key `SIP_KEY`) because the provisioning service must write them into the phone's configuration file.
- Authentication is SIP digest, **SHA-256 (RFC 8760) and MD5** offered together: modern phones pick SHA-256, older ones fall back to MD5. After 20 failed attempts a source IP is refused for 10 minutes. An account can only register as the extension of its owner.

## Add a phone (it_admin)

1. Create the device (the first `it_admin` accounts come from `INITIAL_IT_ADMINS`):

   ```bash
   curl -sk -X POST https://<server>/api/admin/devices -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
     -d '{"user_id": 12, "type": "desk_phone", "vendor": "yealink", "model": "T33G", "mac": "00:15:65:AA:BB:CC"}'
   ```

   The answer contains `sip_username`, `sip_password` (the only time it is shown) and `provisioning_path`.
2. Point the phone at the provisioning server (see below) and power-cycle it: it downloads `https://<server>/prov/<mac>.cfg`, registers, and shows the extension.
3. Check `GET /api/admin/devices`: `registered: true`.

`DELETE /api/admin/devices/{id}` disables a device and frees its MAC for a replacement phone.

## Provisioning URL per vendor

The server serves `https://<server>/prov/<mac>.cfg` (Yealink and Fanvil; MAC in lower case without separators) and `https://<server>/prov/cfg<mac>.xml` (Grandstream).

| Vendor | Where to set the URL | Notes |
|---|---|---|
| Yealink (T3x/T4x/T5x) | Web UI: Settings > Auto Provision > Server URL, or DHCP option 66 | Phones first ask for `y000000000000.cfg`; the 404 is expected. Keys: `account.1.*`, G.711 first. |
| Grandstream (GRP/GXP) | Maintenance > Upgrade and Provisioning > Config Server Path | XML with P-values (`P47` server, `P35` user, `P36` auth name, `P34` password). |
| Fanvil (X/H series) | System > Auto Provision > Server URL | Text format with a `--SIP1 Config--` section. |

**Validate the templates on one phone of each model and firmware before a mass roll-out**: vendors change keys between firmware releases and these templates have not been tested on physical phones yet. They live in `services/provisioning/render.go`.

**Security.** The files contain the SIP password. Serve them only over HTTPS and expose `/prov/` only to the voice VLAN (restrict it in `nginx/templates/default.conf.template` or on the firewall). The service rate-limits per IP and refuses unknown or disabled devices.

## Network requirements

| Port | Purpose |
|---|---|
| 443/tcp | web app, API, WebSocket, provisioning |
| 5060/udp and tcp | SIP signaling |
| 5061/tcp | SIP over TLS (certificate from `SIP_TLS_CERT` and `SIP_TLS_KEY`) |
| 10000-10200/udp | RTP: lower half for WebRTC (PCs), upper half for SIP phones |
| 3478/udp and tcp, 49152-49200/udp | TURN |

Phones behind NAT work: the server answers to the source address of each request (not to the `Contact`) and locks onto the RTP stream at the first packet received (symmetric RTP). Set a registration refresh of 60 s or less on phones behind a NAT so the mapping stays open.

## Analog phone with an ATA

Plug the existing analog phone into an ATA (for example Grandstream HT801/HT802 or Cisco SPA112) and treat the ATA as a desk phone:

1. Create a device of type `desk_phone` with the ATA's MAC and `vendor: grandstream`.
2. Point the ATA at the provisioning server (Grandstream: Advanced Settings > Config Server Path). Port 1 registers with the user's extension.
3. Set the ATA's codec to PCMU first and DTMF to RFC 2833 (payload 101).
4. Fax and modems are not supported on this path.

## What happens to a call

- A call to an extension rings **every** registered desk phone **and** the user's PC. The first device that answers wins; the others get a SIP `CANCEL` (phones) or stop ringing (PC).
- Status effects: *Do not disturb* and *busy* answer `486 Busy Here`; a colleague who has not clocked in answers `480 Temporarily Unavailable`; *Away* forwards to the delegate chosen with `PUT /api/me/delegate`; *In a meeting* rings silently on the PC.
- Audio is G.711 mu-law (PCMU) between a phone and the media server. A PC in the same call switches to G.711 too (see docs/calls.md). PC-to-PC calls keep Opus.

## Not implemented yet

- Phone-initiated transfer (SIP `REFER`) and supervised transfer. Transfer from the PC app works.
- Sync of the Do Not Disturb key with the server (`as-feature-event`).
- SRTP and mandatory SIP over TLS for phones (phase 7 hardening): today RTP is unencrypted on the internal network.
- External trunk and `0`-prefix dialling (interface planned, disabled).
- Voicemail storage: the `480` and `486` answers are where it will hook in.
- Tests on physical Yealink, Grandstream and Fanvil phones.
